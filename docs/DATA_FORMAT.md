# Data and Result Formats

## Run Directory

A typical Vbr run has this structure:

```text
vbr_search_YYYYMMDD_HHMMSS/
├── configuration.json
├── manifest.json
├── run.log
├── pre_environment.json
├── post_environment.json
├── bias/
├── raw/
│   └── bias_054p000/
│       ├── SIPM1/
│       │   ├── capture_metadata.json
│       │   ├── event_status.csv
│       │   └── event_000000.csv ...
│       └── SIPM2/
├── analysis/
│   └── bias_054p000/SIPM1/
│       ├── pulse_measurements.csv
│       ├── peak_fits.csv
│       ├── area_peak_fits.csv
│       ├── point_summary.json
│       ├── pulse_height_peaks.png
│       └── pulse_area_peaks.png
└── results/
    └── SIPM1/
        ├── height/
        └── area/
```

The zero-event and dark workflows use the same principles but organize point folders around overvoltage.

## Waveform CSV

The first three lines describe names, units, and origin. Numerical data begin on line four.

One- or two-channel capture:

```text
Time,Channel A,Channel B
(ns),(mV),(mV)
Generated by automated_vbr_scan
-200.0,0.2,-0.1
...
```

Four-channel reference capture:

```text
Time,Channel A,Channel B,Channel C,Channel D
(ns),(mV),(mV),(mV),(mV)
Generated by pico_scintillator_capture
...
```

Saved voltages already include the configured probe attenuation. `capture_metadata.json` records that attenuation and the requested range.

## Event Status

For self-trigger capture:

```text
event,overflow_mask
0,0
```

For four-channel capture:

```text
event,overflow_mask,elapsed_s
0,0,0.214
```

The overflow mask comes from the PicoSDK. Analysis excludes overflowed events where implemented. The elapsed value is wall time since capture started; it is not a dead-time-corrected event timestamp.

## Point Summary

`point_summary.json` contains the bias, SiPM and channel identity, number of files, accepted/rejected events, baseline/noise summaries, height spacing and uncertainty, area spacing and uncertainty, selected peak count, fit quality, and quality-pass flags. It is the input to `fit_vbr.py`.

## Vbr Results

For each SiPM and metric:

- `all_bias_points.csv` contains accepted and rejected point summaries;
- `vbr_fit.json` contains slope, intercept, covariance-derived uncertainty, reduced chi-square, R², and Vbr;
- `vbr_fit.png` shows only points admitted to the line fit.

Rejected points remain in `all_bias_points.csv` for auditability.

## Zero-Event Results

- `reference_candidate_measurements.csv`: reference pulse measurements before final event selection;
- `selected_event_measurements.csv`: charge and classifications for accepted reference tracks;
- `scintillator_zero_summary.csv` and `.json`: zero counts, dark zero counts, efficiency, uncertainty interval, and occupancy;
- `scintillator_zero_test.png`: diagnostic distributions and result summary.

## Manifest

`manifest.json` is the run index. It records workflow, mode, timestamps, point status, errors, completion, and final hardware state. A directory containing plots is not necessarily a completed run; check the manifest.

## Archiving

Archive the full time-stamped run without renaming internal folders. Record a checksum for publication-grade data:

```bash
tar -czf vbr_search_YYYYMMDD_HHMMSS.tar.gz vbr_search_YYYYMMDD_HHMMSS
sha256sum vbr_search_YYYYMMDD_HHMMSS.tar.gz > vbr_search_YYYYMMDD_HHMMSS.tar.gz.sha256
```

Do not commit bulk waveform files to Git. Commit analysis code, configuration templates, compact tables, and selected figures; place the raw archive in managed laboratory storage.
